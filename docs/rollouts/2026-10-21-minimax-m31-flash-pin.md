# 2026-10-21 — Pin Fleet Autofix to MiniMax-M3.1-Flash and Trust the swu-* Fleet Bots

## Summary

The fleet autofix lanes now bill the `MiniMax-M3.1-Flash` model id on both routes they use.  `.github/pr-autofix-trusted.yml` moves off the retired `MiniMax-M3.1-Flash-Preview` id, `.github/workflows/claude-code-autofix.yml` passes `model: MiniMax-M3.1-Flash` explicitly so it never inherits the pinned reusable workflow's Preview default, and `.github/workflows/kody-fleet-autofix.yml` runs `MiniMax-M3.1-Flash` against the OpenAI-compatible endpoint `https://api.minimax.io/v1` under the renamed display name `Kody MiniMax M3.1 Flash Fix Proposals`.

The owner ruling of 2026-10-20 trusts every `swu-*` fleet bot, so `allowed_bots` in `claude-code-autofix.yml` grows to the 40 confirmed `swu-*` app installations in the organization, each in bare and `[bot]` form, alongside the Codex, Kody, Cursor, Claude, and Sentry identities.  The autofix prompt was updated to name the same set, so the allowlist and the prompt agree.

Branch: `autofix/minimax-flash-and-swu-bots`.  Pull request [#225](https://github.com/Simple-With-Us/Personal-Site/pull/225).

## Verification

`https://api.minimax.io/v1/models` lists `MiniMax-M3.1-Flash`, and a synthetic one-word canary against `https://api.minimax.io/v1/chat/completions` returned HTTP 200 with `model: MiniMax-M3.1-Flash`.  The id therefore resolves on the OpenAI-compatible route that the Kody lane bills, not only on the Anthropic-compatible route.

## Open fleet items

- A per-repository `daily_attempt_limit` for the Claude Code autofix lane is parked on the owner's fleet-budget decision: the owner ruled on 2026-10-20 that no per-repository run cap lands in this PR, and that the fleet-wide autofix scheduling policy is designed separately.  The Claude Code lane calls `congress-trading-shared/.github/workflows/codex-autofix-reusable.yml`, which never reads `.github/pr-autofix-trusted.yml` and takes no cap input, so the cap needs a new `daily_attempt_limit` input on that reusable helper that `claude-code-autofix.yml` passes, the way `kody-fleet-autofix.yml` passes `daily_attempt_limit: 5`.  `.github/pr-autofix-trusted.yml` stays reserved for the coordinator lane behind `.github/workflows/autofix.yml`, whose trusted-file schema has no daily-cap key.
- `.github/workflows/kody-fleet-autofix.yml` is generated by `congress-trading-shared/.github/kody-autofix/generate-caller.mjs`.  That generator divergence is already fixed upstream in `congress-trading-shared` pull request [#393](https://github.com/Simple-With-Us/congress-trading-shared/pull/393): commit `7a26d0b` makes `generateCaller()` derive the display name from `config.model` (`Kody ${config.model.replaceAll('-', ' ')} Fix Proposals`) and sets `DEFAULT_MODEL` to `MiniMax-M3.1-Flash`, so regenerating the caller no longer restores `Kody MiniMax M3 Fix Proposals` or `model: 'MiniMax-M3'`.  Upstream #393 is still open, so the phase-2 pin advance is still outstanding: the four trusted-helper `ref:`s on `kody-autofix-reusable.yml` are still `d06ac2d47bc3b9182ea43deee9f0a91ffdf33ab0` on `main`, which means this repo's caller pin `31659885f58f08e129b6dc092f3493d7cdb74a11` keeps resolving the old helper until that advance lands.  The caller checked in here already matches what the fixed generator emits apart from the repo-specific `repository_id` and `source_prefixes`, so nothing in this repo needs regenerating.
- The Claude Code lane's turn budget is the reusable's own `--max-turns 120` default, because `claude-code-autofix.yml` passes no `claude_args`.  The `max_turns: 60` in `.github/pr-autofix-trusted.yml` binds only the coordinator lane behind `.github/workflows/autofix.yml`; the Claude Code lane's reusable never reads that file.  Passing `claude_args: "--max-turns 60 --allowedTools \"Edit,Write,Read,Bash\""` from the caller would align it.
- `allowed_bots` is a hand-maintained enumeration with no prefix support, so a newly installed fleet app bot is denied silently rather than loudly.
- The Kody lane's helper disables MiniMax reasoning only for the exact id `MiniMax-M3`, so the `MiniMax-M3.1-Flash` id sends `reasoning_split` and re-enables reasoning.  That re-opens the upstream answer-truncation risk the 2026-10-11 note recorded as the reason for disabling reasoning, because `LIMITS.outputTokens` is still 16,384 and `LIMITS.modelMs` is still 240,000 ms.  The fix does **not** belong in the exact-id reasoning disable: `MiniMax-M3.1-Flash` answers HTTP 400 to `thinking: {type: 'disabled'}` and to `reasoning_effort: 'none'`, and treats an omitted effort as `max` (`Simple-With-Us/BotFleet/server/drivers/minimax.ts`; the same constraint is called out in upstream #393), so widening that disable to the new id would make every paid run fail outright rather than shorten its answers.  The remedy upstream #393 implements instead is to keep `reasoning_split` and raise the output budget for the reviewed M3.1 id to 32,768 (`MINIMAX_OUTPUT_TOKENS`), leaving the shared 16,384 cap in place for other providers.  That lands with the phase-2 pin advance above, so the truncation risk stays open here until the pin moves.
